## 1. ⚙️ 核心配置与行为控制 (Configuration)

用于调整 AI 模型的基础能力、权限、记忆和性格。

### `/model`
* **功能说明**：选择当前使用的 AI 模型以及推理努力程度（Reasoning Effort）。
* **使用场景**：当需要处理复杂逻辑时切换到高级模型（如 GPT-4o / Claude 3.5 Sonnet），日常小修改切换到快速模型。
* **💡 用法 Demo**：
  直接在终端输入 `/model`，会弹出一个交互式菜单供你按方向键选择。

### `/permissions`
* **功能说明**：配置 Codex 的执行权限。决定 AI 是否可以直接执行 Shell 命令、修改文件等。
* **使用场景**：防止 AI 在未经允许的情况下执行高危命令（如 `rm -rf`），可设置为“执行前必须询问”。
* **💡 用法 Demo**：
  输入 `/permissions` 呼出权限面板进行勾选。

### `/personality`
* **功能说明**：设置 Codex 的沟通风格。
* **使用场景**：如果你觉得 AI 废话太多，可以将其设置为“简短直接只给代码”；如果需要学习指导，可以设置为“详细解释”。
* **💡 用法 Demo**：
  输入 `/personality` 选择预设的性格。

### `/memories`
* **功能说明**：配置 AI 的记忆使用和生成。
* **使用场景**：让 AI 记住你的代码风格偏好、项目特定的缩进要求或架构规范。
* **💡 用法 Demo**：
  输入 `/memories` 管理当前的记忆库，或者告诉它：“请记住：以后所有的数据库查询都要加索引限制。”

### `/experimental`
* **功能说明**：开启或关闭实验性（Beta）功能。
* **💡 用法 Demo**：
  输入 `/experimental` 切换状态。

## 2. 💬 会话与上下文管理 (Session & Context)

在长周期开发中，管理好对话上下文是防止 AI “幻觉”和超出 Token 限制的关键。

### `/new`
* **功能说明**：在当前对话进行中，快速开启一个全新的聊天会话。
* **💡 用法 Demo**：`/new`

### `/clear`
* **功能说明**：清空当前终端屏幕，并同时开启一个全新的对话（舍弃之前的上下文）。
* **💡 用法 Demo**：`/clear`

### `/resume`
* **功能说明**：恢复之前保存的某个历史会话。
* **💡 用法 Demo**：
  输入 `/resume`，从历史列表中选择昨天下班前未完成的工作流继续。

### `/fork`
* **功能说明**：从当前会话的当前状态派生（Fork）出一个新的独立会话。
* **使用场景**：面临两种技术实现方案，你想先在 Fork 的分支里试试方案 A，不行的话还能回到主会话。
* **💡 用法 Demo**：`/fork`

### `/side`
* **功能说明**：在一个短暂的（ephemeral）分支中开启旁支对话。
* **使用场景**：在主线写代码时，突然忘记了一个正则怎么写，为了不污染主干上下文，开个 side 问一下。
* **💡 用法 Demo**：
  `/side 帮我写一个匹配邮箱格式的正则表达式`

### `/compact`
* **功能说明**：压缩/总结当前长对话的上下文。
* **使用场景**：对话太长导致触及大模型的 Token 上限报错时使用。AI 会将之前的废话浓缩成核心要点保留。
* **💡 用法 Demo**：`/compact`

### `/rename`
* **功能说明**：重命名当前会话的标题，方便以后在历史记录中查找。
* **💡 用法 Demo**：
  `/rename 修复支付接口的回调Bug`

### `/archive`
* **功能说明**：归档当前会话并退出程序。
* **💡 用法 Demo**：`/archive`

## 3. 🚀 Agent 与工作流引擎 (Agent & Workflow)

让 Codex 成为你自动化的智能同事。

### `/plan`
* **功能说明**：切换到“计划模式 (Plan Mode)”。
* **使用场景**：在写代码之前，先让 AI 帮你生成架构设计、步骤拆解和伪代码。
* **💡 用法 Demo**：
  `/plan 我们现在要做一个用户注册模块，需要包含邮箱验证，请先帮我梳理出需要修改和创建哪些文件。`

### `/goal`
* **功能说明**：为长时间运行的任务设定或查看最终目标。
* **💡 用法 Demo**：
  `/goal 将整个项目从 Vue2 迁移到 Vue3，并确保所有单元测试通过。`

### `/init`
* **功能说明**：在项目根目录生成一个 `AGENTS.md` 文件。
* **使用场景**：用于在该文件中持久化编写针对当前项目的全局指令、AI 行为准则。
* **💡 用法 Demo**：在项目根目录输入 `/init`。

### `/agent` & `/subagents`
* **功能说明**：切换当前激活的 Agent 线程/子 Agent。
* **使用场景**：如果你配置了多个专职的 Agent（比如专门负责写测试的 Agent，专门负责检查安全性的 Agent），可以用此命令切换。
* **💡 用法 Demo**：
  输入 `/agent` 选择你的专属 Agent。

### `/skills`
* **功能说明**：使用或配置“技能 (Skills)”来提升 Codex 执行特定任务的能力。
* **💡 用法 Demo**：输入 `/skills` 查看并启用相关技能插件。

### `/hooks`
* **功能说明**：查看和管理生命周期钩子 (Lifecycle hooks)。
* **使用场景**：配置在特定事件发生时自动执行的动作（例如：每次 AI 生成完代码自动运行一下 `npm run lint`）。
* **💡 用法 Demo**：`/hooks`

### `/approve`
* **功能说明**：批准重试一次最近被 Auto-review（自动审查）拒绝的操作。
* **💡 用法 Demo**：当 AI 尝试修改敏感文件被系统拦截时，如果你确认安全，输入 `/approve` 放行。

## 4. 💻 代码审查与 IDE 集成 (Code & IDE)

将 AI 的能力与你的实际代码无缝对接。

### `/ide`
* **功能说明**：读取你当前 IDE (如 VSCode/Cursor) 中的状态，包含当前选中的代码、已打开的文件树等上下文。
* **使用场景**：在 IDE 里高亮一段报错的代码，然后在终端使用此命令让 AI 针对性解答。
* **💡 用法 Demo**：
  `(在 IDE 中选中一段代码) -> 终端输入: /ide 帮我解释一下这段逻辑存在什么性能瓶颈？`

### `/mention`
* **功能说明**：提及并引入特定文件作为上下文。
* **💡 用法 Demo**：
  `/mention src/utils/request.js 请参考这个文件，帮我在 login.vue 里写一下调用逻辑。`

### `/review`
* **功能说明**：审查当前工作区的 Git 变更（类似 Code Review），并寻找潜在的 Issues。
* **💡 用法 Demo**：
  写完一段代码准备 Commit 前输入 `/review`，让 AI 看看有没有明显的 Bug。

### `/diff`
* **功能说明**：显示当前工作区的 git diff，包含未追踪（untracked）的新文件。
* **💡 用法 Demo**：`/diff`

### `/sandbox-add-read-dir`
* **功能说明**：允许安全沙盒（Sandbox）读取指定的绝对路径目录。
* **使用场景**：当项目需要依赖外部目录的配置文件时。
* **💡 用法 Demo**：
  `/sandbox-add-read-dir /Users/admin/my_local_config/`

## 5. 🔌 插件与外部工具 (Plugins & Tools)

### `/mcp`
* **功能说明**：列出当前配置的 MCP (Model Context Protocol) 工具。MCP 允许大模型以标准化的方式调用外部工具和数据源。
* **💡 用法 Demo**：
  * `/mcp` (简单列表)
  * `/mcp verbose` (查看每个工具的详细信息和参数)

### `/plugins`
* **功能说明**：浏览和管理 Codex 扩展插件。
* **💡 用法 Demo**：`/plugins`

## 6. 🎨 终端 UI 与个性化 (TUI & Personalization)

定制化你的命令行视觉体验和交互逻辑。

### `/theme`
* **功能说明**：选择代码块的语法高亮主题。
* **💡 用法 Demo**：输入 `/theme` 选择如 `Monokai`, `Dracula`, `Github Dark` 等。

### `/vim`
* **功能说明**：开启/关闭输入框的 Vim 模式（支持普通模式、插入模式等按键绑定）。
* **💡 用法 Demo**：如果你是 Vim 党，输入 `/vim` 即可使用 `hjkl` 和 `i` 等按键交互。

### `/keymap`
* **功能说明**：重新映射 TUI (终端用户界面) 的快捷键。
* **💡 用法 Demo**：`/keymap`

### `/status`
* **功能说明**：显示当前会话的配置详情以及 Token 的消耗/使用量统计。
* **💡 用法 Demo**：`/status`

### `/title` & `/statusline`
* **功能说明**：配置终端标题栏 (`/title`) 或底部状态栏 (`/statusline`) 显示哪些项目（如消耗、模型名称、耗时等）。

### `/copy`
* **功能说明**：将 AI 最后一次回复的内容以纯 Markdown 格式复制到系统剪贴板。
* **💡 用法 Demo**：`/copy`

### `/raw`
* **功能说明**：切换“原生滚动”模式。
* **使用场景**：在某些终端模拟器中，直接用鼠标选中复制 AI 代码会被 UI 边框打断，开启 `/raw` 后终端将转为纯文本输出流，方便鼠标直接拖拽大段复制。
* **💡 用法 Demo**：`/raw`

### `/pets`
* **功能说明**：在终端角落显示一只可爱的字符宠物，或隐藏它（纯属娱乐和解压功能 🐶）。
* **💡 用法 Demo**：输入 `/pets` 挑选你的赛博宠物。

## 7. 🛑 系统与进程控制 (System)

### `/fast`
* **功能说明**：开启 1.5 倍加速模式（注：可能会增加 API 额度使用量）。
* **💡 用法 Demo**：`/fast`

### `/ps`
* **功能说明**：列出当前后台正在运行的所有终端任务（比如让 AI 在后台去跑一个巨大的构建任务）。
* **💡 用法 Demo**：`/ps`

### `/stop`
* **功能说明**：强制停止所有后台的终端任务。
* **💡 用法 Demo**：当 AI 陷入死循环跑脚本或者测试卡死时，使用 `/stop`。

### `/feedback`
* **功能说明**：将当前的日志打包发送给 Codex 维护者，用于报告 Bug。
* **💡 用法 Demo**：`/feedback 遇到了生成代码后终端崩溃的问题`

### `/logout`
* **功能说明**：注销当前账号。
* **💡 用法 Demo**：`/logout`

### `/exit`
* **功能说明**：安全退出当前 Codex 命令行工具。
* **💡 用法 Demo**：`/exit`
